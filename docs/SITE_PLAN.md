> 작성 2026-10-08 · 상태: **설계 보고(구현 전)** · 대상: 인천·김포·부천, 동 단위까지
> 유사도·검색·AI 노출 설계는 `SEO_PLAN.md`, 유사도 검사 도구는 `tools/page_similarity.py`

## 0. 한 줄 요약

v3 시안을 메인 페이지로 두고, **지역 데이터(시 → 구 → 동)와 실제 작업 사례 데이터**로 지역 페이지를 자동 생성하는 정적 사이트로 만듭니다.
다만 동 이름만 바꾼 페이지를 수백 장 찍어 내면 네이버·구글 모두 **저품질·중복 문서**로 보고 노출을 오히려 떨어뜨립니다. 그래서 **각 페이지에 그 동에서만 쓸 수 있는 내용이 있을 때만 공개**하는 단계형으로 설계했습니다.

## 1. 목표와 전제

| 항목 | 내용 |
|---|---|
| 목표 | "○○동 제빙기 청소" 같은 지역 검색에서 네이버 **웹사이트 영역**에 노출, 상담 신청·전화로 연결 |
| 메인 페이지 | `icelab/v3` 그대로 (로고·전화 반영본) |
| 지역 | 인천광역시, 김포시, 부천시 |
| 단위 | 시 → 구·군 → 행정동(읍·면 포함) |
| 기술 | 정적 사이트(서버·DB 없음). 빌드 시 데이터로 페이지 생성 → 무료 호스팅 배포 |

**노출에 대한 정직한 전제**
- 검색 노출(웹사이트 영역에 여러 개가 묶여 보이는 것 포함)은 검색엔진이 정하며 **보장할 수 없습니다.** 설계로 할 수 있는 것은 "수집이 잘 되고, 문서마다 고유한 가치가 있게" 만드는 것까지입니다.
- 제빙기 청소 같은 출장 서비스는 실제로는 **네이버 스마트플레이스(지도·플레이스 영역)** 에서 문의가 더 많이 옵니다. 홈페이지와 별도로 등록을 권합니다(사업자등록 필요).

## 2. 지역 범위 (데이터 확인 필요)

> 아래 숫자는 설계용 추정입니다. 구현 전 **행정안전부 행정표준코드(행정동 코드) 최신본**으로 확정합니다.

| 시 | 구·군 | 동 단위 규모(추정) | 비고 |
|---|---|---|---|
| 인천광역시 | 9구 2군 | 약 150~160 | **2026-07-01 행정체제 개편 반영 필요**: 중구·동구 → 제물포구·영종구, 서구 → 서구·검단구. 옛 구 이름으로 검색하는 사람도 있어 페이지 안에 "(옛 중구)" 식으로 병기 |
| 부천시 | 3구(원미·소사·오정, 2024 부활) | 약 35~40 | |
| 김포시 | 구 없음 | 약 13~14 (읍·면·동) | 시 → 바로 동 |

**결정 필요**: 옹진군 섬 지역과 강화군을 서비스 지역에 넣을지(출장 가능 여부). 출장이 어려운 곳은 페이지를 만들지 않는 것이 맞습니다.

## 3. 사이트 구조 (URL)

```
/                                   메인 (v3)
/area/                              서비스 지역 전체 (지도 + 목록)
/area/incheon/                      인천 (구·군 목록)
/area/incheon/namdong-gu/           남동구 (동 목록 + 구 단위 사례)
/area/incheon/namdong-gu/guwol-1/   구월1동  ← 동 페이지
/area/gimpo/                        김포 (구 없음 → 바로 동 목록)
/area/gimpo/unyang/                 운양동
/area/bucheon/wonmi-gu/jung-1/      ...
/cases/                             작업 사례 목록
/cases/2026-10-07-guwol-cafe/       작업 사례 1건 (전후 사진·기종·기록지)
/price/  /faq/  /contact/           (메인에서 분리 가능한 공통 페이지, 선택)
/privacy/                           개인정보처리방침 (폼 운영 시 필수)
/sitemap.xml  /robots.txt
```

- 주소는 **영문 로마자**(`guwol-1`)로, 제목·본문은 한글로. 한글 주소는 공유할 때 `%EA%B5%AC…`로 깨져 보입니다.
- 모든 페이지에 **이동 경로(빵부스러기)**: 홈 > 서비스 지역 > 인천 > 남동구 > 구월1동.

**페이지 수(전부 공개 시)**: 허브 약 17장(지역 전체 1 + 시 3 + 구·군 14) + 동 약 200장 + 사례 n장.

## 4. 동 페이지 설계 (핵심)

### 4-1. 화면 구성
v3와 같은 디자인 체계를 쓰되, 지역 정보가 앞에 옵니다.

1. **H1**: "구월1동 제빙기 청소" + 한 줄 답: "구월1동은 평일·주말 출장, 50kg 이하 10만원부터."
2. **이 동의 출장 정보**: 기준지에서 거리·평균 도착 시간, 가능한 시간대 (계산값)
3. **이 동의 작업 사례** ← 가장 중요한 고유 내용
   전후 사진, 업종(카페·식당·PC방), 기종·용량, 발견된 문제, 작업일. 사례 페이지로 연결
4. **주변 상권 메모**: 그 동의 주요 상권·카페거리 등 (사람이 직접 쓴 2~4문장)
5. 가격(메인과 동일한 표), 작업 5단계(요약)
6. **이 동에서 받은 질문**(있을 때만): 실제 문의에서 나온 질문
7. 상담 신청(전화·카톡·폼), **이웃 동 링크** 4~6개, 상위 구 페이지 링크

### 4-2. 공개 기준 (저품질 판정 피하기)
| 등급 | 조건 | 처리 |
|---|---|---|
| A | 실제 작업 사례 1건 이상 + 상권 메모 | **공개(색인)** |
| B | 사례 없음, 상권 메모·출장 정보만 | 공개하되 **구 페이지로 대표 주소(canonical)** 지정, 또는 비공개 |
| C | 이름만 있음 | **만들지 않음** (구 페이지의 동 목록에만 이름 표시) |

- 사례가 쌓이면 B → A로 자동 승격(빌드 때 판정).
- 동 이름만 바꾼 문장 템플릿, AI로 늘린 설명문은 쓰지 않습니다. 네이버 검색 품질 기준의 "반복·자동 생성 문서", 구글의 "대량 생성 콘텐츠·도어웨이" 정책에 정확히 걸리는 형태입니다.

### 4-3. 구·시 페이지
- 소속 동 목록(공개 등급 표시 없이 이름 전부, A/B만 링크), 그 구의 사례 모음, 구 단위 출장 정보.
- 동 페이지가 적은 초기에는 **구 페이지가 주력 검색 페이지** 역할을 합니다.

## 5. 데이터 설계

빌드는 이 두 파일만 고치면 됩니다. (엑셀로 관리 → CSV로 내보내도 됨)

**`data/regions.json`** (지역)
```json
{
  "slug": "guwol-1", "name": "구월1동", "code": "행정동코드",
  "city": "incheon", "gu": "namdong-gu", "guLegacy": null,
  "neighbors": ["guwol-2", "ganseok-1", "mansu-1"],
  "travelMin": 35, "note": "로데오거리·예술회관역 주변 카페 밀집 …(사람이 작성)",
  "serviceable": true
}
```

**`data/cases.json`** (작업 사례)
```json
{
  "id": "2026-10-07-guwol-cafe", "date": "2026-10-07", "dong": "guwol-1",
  "placeType": "카페", "brand": "호시자키", "capacityKg": 50,
  "issues": ["분배관 곰팡이", "증발판 석회"],
  "before": "cases/2026-10-07/before.jpg", "after": "cases/2026-10-07/after.jpg",
  "comment": "6개월 만의 청소, 얼음 생산량 저하 문의", "consent": true
}
```
- 사례 사진은 **매장 동의(consent)** 가 있을 때만 공개, 간판·사람 얼굴은 가림.
- 작업 후 기록지(카톡 PDF)를 만들 때 이 형식으로 한 줄씩 쌓이게 하면 사이트 갱신이 자동으로 됩니다.

## 6. 검색 노출 설정

| 항목 | 내용 |
|---|---|
| 네이버 서치어드바이저 | 사이트 등록·소유 확인(meta), **사이트맵 제출**, 새 페이지 수집 요청, `robots.txt`에서 Yeti 허용 |
| 구글 서치콘솔 | 등록·사이트맵 제출 |
| 제목·설명 | 페이지마다 고유: `구월1동 제빙기 청소 · 분해 세척과 기록지 | 얼음싹싹` |
| 구조화 데이터(JSON-LD) | `LocalBusiness`(상호·전화·서비스 지역), `Service`(areaServed=해당 동), `BreadcrumbList`, 사례 페이지는 `ImageObject` |
| 대표 주소 | 모든 페이지 `canonical` 지정, B등급은 구 페이지로 |
| 사이트맵 | 공개(A·B) 페이지만, `lastmod`는 사례 추가일 |
| 속도 | 이미지 WebP·지연 로딩, 글꼴 부분 로딩. 현재 v3 이미지 약 1.9MB → 지역 페이지는 사례 사진 위주로 가볍게 |
| 내부 링크 | 메인 → 서비스 지역 → 시 → 구 → 동, 동 ↔ 이웃 동, 사례 ↔ 동 |

## 7. 기술·배포

| 항목 | 제안 | 이유 |
|---|---|---|
| 생성 도구 | **Astro**(정적 출력) | v3 HTML/CSS를 거의 그대로 컴포넌트로 옮김, 사이트맵·이미지 최적화 기본 제공. 대안: Node 스크립트로 직접 생성(의존성 최소) |
| 저장소 | **새 저장소**(예: `eoreumssakssak-site`) | 지금은 detective-site 저장소의 브랜치에 섞여 있음 |
| 호스팅 | Cloudflare Pages 또는 Netlify (무료) | 서울 근처 서버, 자동 HTTPS, 커밋하면 자동 배포 |
| 도메인 | `.kr` 또는 `.com` 영문 도메인 1개 (+ 한글 도메인은 연결만) | |
| 상담 폼 | 폼 전송 서비스(예: Formspree·구글폼 연동) 또는 카카오 채널 | 정적 사이트라 서버 없음 |
| 갱신 | `cases.json`에 한 줄 추가 → 커밋 → 자동 빌드·배포·사이트맵 갱신 | |

## 10. 정해 주셔야 할 것

1. **도메인**과 **새 저장소** 생성 여부
2. **서비스 제외 지역**(옹진군 섬, 강화군 등)
3. 거리·도착 시간 계산용 **출발 기준지**(동 단위면 충분)
4. **사업자 정보**(정식 배포 시 푸터 표시)
5. 동 페이지 공개 방식: **A등급(사례 있는 동)부터 단계 공개(권장)** vs 전체 일괄 공개
6. 상담 폼 수신 방식(카톡 채널 / 이메일 / 구글 시트)
