# 얼음싹싹 지역 페이지 · 검색/AI 노출 설계

> 작성 2026-10-08 · `SITE_PLAN.md`(구조)의 짝 문서 · 대상: 인천·김포·부천 시/구·군/동 페이지

## 0. 원칙: "독립 페이지처럼 보이게"가 아니라 "독립 페이지로 만든다"

검색엔진(네이버·구글)과 AI 검색은 페이지를 **겉모양이 아니라 쓸모**로 판단합니다. 글자 바꾸기, 문장 순서 섞기, AI로 동네별 설명 늘리기 같은 "다르게 보이게 하는 기술"은 구글 스팸 정책의 **도어웨이·대량 생성 콘텐츠**, 네이버 검색 품질 기준의 **반복·자동 생성 문서**에 정확히 해당합니다. 걸리면 해당 페이지가 아니라 **사이트 전체 평가**가 떨어집니다.

그래서 이 설계의 기준은 하나입니다.

> **이 동 페이지가 없어지면, 그 동 사장님이 잃는 정보가 있는가?**
> 없으면 페이지를 만들지 않는다.

---

## 1. 페이지 종류별 역할을 겹치지 않게 나누기

같은 질문에 답하는 페이지가 여러 장이면 서로 경쟁합니다(키워드 잠식). 단계마다 **답하는 질문을 다르게** 정합니다.

| 단계 | 답하는 질문 | 이 페이지에만 있는 것 | 다른 단계와 겹치면 안 되는 것 |
|---|---|---|---|
| 메인 | 제빙기 청소 어디에 맡기지? 얼마? | 서비스 전체 설명, 가격 기준, 브랜드, 상담 | 지역 이야기 |
| 서비스 지역 | 우리 지역도 와요? | 시·구 목록, 출장 범위 지도, 제외 지역 | 가격·작업 설명 반복 |
| 시 (3) | 인천(김포·부천) 어디까지 와요? | 구별 사례 수·도착 시간 비교, 시 단위 통계 | 동 단위 사례 상세 |
| 구·군 (14) | 남동구 제빙기 청소 업체? | 구 안 동 목록, 구 단위 사례 모음, 순회 요일, **수질(경도)** | 동별 상세 문장 |
| 동 (공개 기준 통과분만) | 구월1동 제빙기 청소? | **그 동의 실제 작업 사례**, 그 동 상권 메모, 그 동에서 받은 질문 | 가격표·작업 과정 전문(링크로 대체) |

## 2. 동 페이지를 "독립"으로 만드는 재료 (가치 순)

| 순위 | 재료 | 출처 | 고유성 | 비고 |
|---|---|---|---|---|
| 1 | **작업 사례**: 날짜, 업종, 브랜드·모델, 발견한 문제, 한 일, 결과(생산량·냄새 등), 전후 사진 | `data/cases.json` (작업 기록지에서 자동) | 매우 높음 | 사진은 동마다 다름. 매장 동의 필수 |
| 2 | **기사 현장 메모** 2~4문장 | 작업 후 직접 작성 | 높음 | "이 동은 늦게 닫는 매장이 많아 밤 방문이 많다" 같은 관찰 |
| 3 | **그 동에서 실제로 받은 질문** | 전화·카톡 문의 기록 | 높음 | 질문이 없으면 블록을 빼는 게 맞음(만들어 넣지 않음) |
| 4 | **출장 운영 정보**: 기준지에서 거리·시간, 순회 요일, 가능 시간대 | 계산 + 운영 일정 | 중간 | 사실 데이터라 동마다 자연히 다름 |
| 5 | **상권 구성**: 동 안 카페·음식점·PC방 수, 주된 매장 규모 | 공공데이터포털 "소상공인시장진흥공단 상가(상권)정보" (행정동 단위) | 중간 | 숫자 + 그 숫자가 왜 제빙기와 관련 있는지 한 문장 |
| 6 | **수질(경도)** 과 권장 청소 주기 | 인천·김포·부천 상수도 수질 공개자료(정수장별) | 구 단위 | 경도가 높을수록 물때가 빨리 쌓임 → 동 페이지에는 요약 한 줄 + 구 페이지에 상세 |

**쓰지 않는 재료**: 동 이름만 바꾼 소개 문장, AI가 쓴 "○○동은 살기 좋은 동네…" 류 설명, 지역 명소 나열(제빙기와 무관), 다른 동과 같은 FAQ.

## 3. 유사도 관리 (빌드 단계에서 자동 차단)

### 3-1. 측정 도구
`tools/page_similarity.py`: 빌드된 페이지의 본문만 뽑아 한글 3글자 단위로 겹침(자카드 유사도)을 계산합니다. 공통 블록(`data-shared` 표시)은 따로 뺍니다. 기준을 넘으면 **종료 코드 1**로 배포를 막습니다.
`site/build.mjs` 가 빌드 끝에 자동으로 돌립니다.

- **검사 대상은 동 페이지끼리입니다.** 구·시·공통 페이지는 길잡이 역할이라 원래 짧고 틀이 같아서 같은 잣대로 재지 않습니다(참고용으로만 보고).
- **버그 수정(2026-10-08)**: 이 도구가 `<img>`·`<link>` 같은 **닫는 태그가 없는 요소**를 잘못 세어, 그 뒤 본문을 통째로 버리고 있었습니다.
  고치기 전에는 모든 페이지가 "고유 0"으로 나와 검사가 사실상 작동하지 않았습니다.

**데모 결과** (같은 공통 블록, 본문만 다르게)

| 경우 | 두 페이지 유사도 | 페이지당 고유 조각 |
|---|---|---|
| 동 이름만 바꾼 템플릿 (구월1동 ↔ 간석1동) | **0.84** ✗ | 8 ✗ |
| 실제 사례·메모·질문으로 채운 페이지 | **0.11** ✓ | 179~209 ✓ |

### 3-2. 공개 기준 (게이트)
| 등급 | 조건 | 처리 |
|---|---|---|
| A 공개 | 사례 1건 이상 + 현장 메모, **다른 모든 동과 유사도 ≤ 0.45**, 고유 조각 ≥ 60 | 색인 허용, 사이트맵 포함 |
| B 대기 | 출장 정보·상권 수치만 있음 | 페이지는 만들되 `noindex`, 구 페이지로 링크. 사이트맵 제외 |
| C 없음 | 이름만 있음 | 페이지 생성 안 함 (구 페이지 목록에 이름만) |

- 사례가 쌓이면 빌드 때 자동으로 B → A.
- **기준값 정정(2026-10-08)**: 고유 조각 기준을 **600 → 60**으로 내렸습니다.
  600은 이 문서 3-1 표의 "좋은 페이지"(179~209)조차 넘지 못하는 값이라 처음부터 맞지 않았습니다.
  실제 생성기로 측정한 값은 아래와 같고, 둘 사이가 14~140배로 뚜렷해서 60이면 충분히 갈립니다.

  | 페이지 | 유사도 | 고유 조각 |
  |---|---|---|
  | 동 이름만 바꾼 메모 (만수1동 ↔ 만수2동) | **0.94** ✗ | 1, 7 ✗ |
  | 실제 사례·현장 메모 (구월1동, 간석1동) | 0.33 이하 ✓ | 97, 143 ✓ |

- 기준값(0.45, 60)은 첫 20~30개 동이 쌓인 뒤 실제 분포를 보고 다시 조정합니다.
  현장 메모가 길어지면 고유 조각도 늘어나므로 기준을 올릴 수 있습니다.

### 3-3. 공통 블록 줄이기
검색엔진은 공통 블록까지 포함한 **페이지 전체**를 봅니다. 그래서 동 페이지의 공통 부분은 최소로:
- 가격: 표 대신 한 줄 + `/price/` 링크
- 작업 과정: 5단계 이름만 + `/process/` 링크
- 브랜드 목록: 동 페이지에는 **그 동 사례에 나온 브랜드만**
- 헤더·푸터는 공통이어도 무방(검색엔진이 틀로 인식). 단 **푸터에 동 200개 링크 나열 금지**(도어웨이 신호)

### 3-4. 구조로 차이 만들기 (문장 바꾸기가 아니라)
- 데이터 양에 따라 **섹션 구성이 달라짐**: 사례 3건 이상인 동은 사례가 맨 위, 질문이 많은 동은 질문 블록 확대, 사례 1건인 동은 짧은 페이지. 짧은 페이지는 짧게 두는 게 정상입니다(채우려고 늘리지 않음).
- 이미지는 그 동 사례 사진만. 공통 일러스트 반복 최소화.

| 문서 품질 | 원본 사진, 날짜가 있는 기록, 연락처·사업자 정보 명시. 키워드 반복 금지 |
| AI 브리핑 | 네이버 검색의 생성형 요약 영역. 질문형 소제목 + 첫 문장 직답(5장 참고)이 인용되기 쉬운 형태 |

## 6. AI에게 물었을 때 추천되도록 (생성형 검색 최적화)

사용자가 "인천 남동구 제빙기 청소 업체 추천해 줘"라고 물을 때 AI는 **(1) 검색 색인에서 찾고 (2) 여러 출처가 같은 말을 하는 업체**를 고릅니다.

| 항목 | 할 일 | 이유 |
|---|---|---|
| 색인에 들어가기 | 구글 서치콘솔 + **Bing 웹마스터 도구** 등록, **IndexNow**로 새 페이지 즉시 알림 | ChatGPT 검색 등은 Bing 색인을 많이 쓰는 것으로 알려져 있음. 네이버·Bing은 IndexNow 지원(적용 전 최신 지원 여부 확인) |
| AI 검색 로봇 허용 | robots.txt에서 `OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`, `Bingbot`, `Googlebot`, `Yeti` 허용. 학습용(`GPTBot`, `Google-Extended`) 허용 여부는 선택 | 검색용 로봇을 막으면 추천 후보에서 빠짐 |
| 답이 바로 나오는 문장 | 소제목은 질문형("구월1동 제빙기 청소 비용은?"), **첫 문장에 숫자 포함 직답**, 그 다음에 근거 | AI가 인용하기 쉬운 형태 |
| 업체 정체성 일관 | 상호·전화·서비스 지역을 사이트·스마트플레이스·구글 프로필·블로그·당근 비즈프로필에서 **똑같이** 표기, `Organization`/`LocalBusiness`의 `sameAs`로 연결 | 출처끼리 일치해야 같은 업체로 인식 |
| 신뢰 근거 | `/about`: 경력, 사용 약품(식품용 인증), 보험 가입 여부, 작업 건수. 사례마다 날짜·사진 | 경험·전문성 신호 |
| 제3자 언급 | 플레이스·구글 리뷰, 블로그 후기, 지역 커뮤니티 언급 | AI는 자기소개보다 남이 한 말을 더 믿음 |
| llms.txt | 사이트 요약 파일을 두는 것은 비용이 거의 없어 둬도 되지만, **효과가 검증된 표준은 아님** | 과대평가하지 않음 |

**점검 방법(매월)**: ChatGPT·Perplexity·Gemini·네이버에서 "인천 ○○구 제빙기 청소", "부천 제빙기 청소 업체 추천" 등 10개 질문을 같은 문장으로 물어 언급 여부·인용 페이지를 기록.

## 7. 빌드·운영 흐름

```
작업 완료 → 기록지(카톡) 생성 → cases.json 한 줄 추가(사진·동·브랜드·메모·동의)
  → 빌드: 동 페이지 생성 → page_similarity.py 검사 → 통과분만 A등급
  → 사이트맵·RSS 갱신 → IndexNow 알림 → (선택) 블로그 글 발행
```

## 8. 측정 지표

| 지표 | 도구 | 목표 방향 |
|---|---|---|
| 색인된 동 페이지 / 공개 동 페이지 | 서치콘솔, 서치어드바이저 | 90% 이상 유지(낮으면 품질 신호) |
| 동 이름 포함 검색 노출·클릭 | 서치콘솔 검색 실적, 서치어드바이저 | 동 페이지 수보다 클릭 동 수가 중요 |
| AI 답변 언급 | 월간 질문 점검표 | 언급 지역 수 |
| 전화·상담 신청 | `tel:` 클릭, 폼 제출 | 지역별 문의 |

## 9. 하지 않는 것 (명시)

- 동 이름만 바꾼 페이지 일괄 생성, AI로 동네 설명 대량 작성, 문장 순서·동의어 섞기
- 숨긴 텍스트, 키워드 반복, 푸터 대량 지역 링크
- 다른 동 사례를 그 동 사례처럼 표시, 동의 없는 매장 사진
- 가짜 리뷰·후기 작성

## 10. 정해 주셔야 할 것

1. 작업마다 **현장 메모 2~4문장**과 **매장 사진 동의**를 받는 운영 가능 여부 (이게 동 페이지의 원료)
2. 스마트플레이스·구글 비즈니스 프로필 등록 (사업자등록 정보 필요)
3. 블로그 운영 여부
4. AI 학습용 로봇(GPTBot·Google-Extended) 허용 여부
